**Key Technical Concepts**
-   **Station-First API Contract:** The final, non-negotiable architecture for train search. The backend's responsibility is to be strict and predictable, accepting only station codes or explicit  tokens. The frontend is responsible for guiding the user to make a valid selection. This replaced the initial smart backend approach.
-   **Single Source of Truth (URL State):** The UI state for the active service (Flights, Trains, etc.) is managed globally by synchronizing all components (top navigation, hero tabs) with the URL query parameter (). This eliminates inconsistent UI states.
-   **Controlled Autocomplete Components:** All search inputs (Trains, Hotels, Buses) now use controlled components that store the full selected object in state, not just a raw text string. This prevents invalid submissions and enables robust validation.
-   **Route-Aware UX:** The frontend now contains logic () to determine if a route is domestic or international, allowing it to present more intelligent and relevant suggestions on no results pages without extra API calls.
